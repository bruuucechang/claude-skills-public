# 區塊：一個 session 做一塊，做完就把前文丟掉

## 這個 skill 要解決的是錢的問題，不是整潔的問題

2026-09-25 實測（Air 近 7 天 17,775 個助理輪次）：

```
每輪 context 中位數 429k   p95 922k   最大 1000k（視窗就是 1M）
cache_read 佔全部 token 的 98.5%
最貴的單一 session：7,673 輪 / 10,079 分鐘（七天沒關）→ 吃掉那週 25%
```

**錢不是花在做事，是花在每一輪把整份累積的前文重讀一次。** 唯一真正有效的
止血是「做完一段就把那段的前文丟掉」，而要敢丟，得先有兩樣東西：

1. **這一塊做完的判準**（`blocks.md` 的驗收指令）
2. **下一塊的起手**（交接單，照 `handoff` skill 寫）

收那一下由 `handoff-open` 自動做（2026-10-20 起）：回合結束後同一格自己 `/clear`、讀交接單接著做。
這個 skill 做的是讓收變成無損的：每塊有驗收判準、做完就寫好交接單。

## 三種用法

### 一、切塊（開工前）

**先 grilling，再切塊。** 沒問成規格就切，切出來的是猜的。用 `grilling` skill
把「目標、輸入輸出、邊界、驗收怎麼算、明確不做什麼」問到齊，然後才寫 `blocks.md`。

一塊的大小判準是**能不能在一個 session 裡做完並驗收**。實測的體感刻度：
一塊大約對應 40–120 個助理輪次、context 從 ~35k 長到 200–400k。切太大的症狀是
做到一半 context 就過 500k（`context-tier` hook 會講）；切太小的症狀是
每塊的固定開場成本（~35k）佔比太高。

格式（放 repo 根，跟 `project-map.json` 並排，進版控）：

```markdown
# 區塊計畫：<專案>

> 一個 session 做一塊。做完跑驗收 → 打勾 → 寫 HANDOFF → 關掉開新的。

## B1 把匯入改成串流  [完成]
- 目標：匯 10MB 的檔不要把記憶體吃爆
- 驗收：`npm test` 綠，且 `node tools/import.mjs fixtures/10mb.csv` RSS < 300MB
- 碰：`backend/import.py`、`tests/import.test.ts`
- 不做：前端進度條（那是 B2）

## B2 前端進度條  [進行中]
- 目標：匯入時畫面上看得到百分比
- 驗收：`npm test` 綠 ＋ dev-browser 截圖看得到百分比在動
- 碰：`frontend/src/Import.tsx`
- 不做：失敗重試（B3）
```

四個欄位都是必要的，少一個就會出事：

| 欄位 | 少了會怎樣 |
|---|---|
| **目標** | 做著做著變成另一件事 |
| **驗收** | 「做完了」變成感覺，而不是跑得出來的指令 |
| **碰** | 這一塊會動到哪些檔，下一個 session 不必重新摸索 |
| **不做** | **最容易漏、也最重要**：沒有它，一塊會自然長大到吃掉整個計畫 |

狀態只有四個：`[未開始]` `[進行中]` `[完成]` `[封存]`。
`blocks-current` hook 靠 `## <標題>  [狀態]` 這個形狀解析，**不要改標題的格式**。

⚠️ **這個檔會被每個 session 讀到，所以它會漂。** 今天才在 palrogue 的
`HANDOFF.md` 上證明過同一件事：沒有上限的「長期區域」會長到 1.39 MB，
而 30% 的輪次因此每輪多送 67 萬字元。所以**完成的區塊累積到 10 塊就移進
`blocks-done.md`**（那個檔不會被注入、也不會被讀，只是留著可以翻）。

### 二、做一塊

全新開的 session 由 SessionStart hook（`blocks-current`）注入「現在該做哪一塊」；`/clear` 換手後不會注入，
以交接單的「下一步」為準（交接單照 `handoff` skill 寫，要寫明是哪一塊），讀完直接開始。

- **一個 session 只做一塊。** 做完不要在同一個 session 接著做下一塊——收一塊（下面第 5 步）會自己換手，下一塊由清完的 session 做。
- 中途冒出來的、不屬於這一塊的東西：**寫進 `blocks.md` 當新的一塊**，不要順手做掉。
  專案用碎片檔的（animyria：`docs/blocks.d/<塊>.md`，見它的 AGENTS.md「共用文件寫碎片檔」）就照專案的寫，
  並行的 lane 才不會改同一個檔；SessionStart hook 兩邊都讀。
  （這跟全域規則「只做被交代的範圍」是同一條，只是有地方放了。）
- `context-tier` hook 在 500k 會叫你 `/compact`。在區塊計畫底下那通常代表
  **這一塊切太大了**——記下來，下次切小一點。

### 三、收一塊

順序固定，少一步就白做：

1. **跑那一塊自己的驗收指令**，親眼看過輸出。沒過就不是做完，狀態留 `[進行中]`。
2. `blocks.md` 那一塊改成 `[完成]`（塊在碎片檔裡就改碎片檔；落地紀錄照專案規矩寫，animyria 寫 `docs/blocks.d/<塊>.md`）。
3. commit ＋ push（驗證乾淨就直接推，不用問——那是常設授權）。
4. **照 `handoff` skill 寫交接單**（`$SCRATCHPAD/handoff/<主題>.md`）：講「上一塊做完了什麼、
   下一塊從哪裡起手、踩到什麼下一個 session 要知道」。
5. **自己換手**：交接單寫好就跑 `handoff-open <交接單>`，回合結束後這格會自己 /clear、讀交接單、
   /recon 之後直接做下一塊。不用叫使用者動手，也不問。

## 沒有重大事件就一路做下去（2026-10-19 裁示）

使用者原話：「沒有重大事件的話 自己clear自己就繼續工作了 不要再問我」。
所以 `blocks.md` 已經寫好的區塊**不再等他下令**，一塊接一塊做到全部打勾。

**重大事件**（只有這些才停下來用選項問）：
- 不可逆／刪資料、花錢、對外發布、要密碼或登入、碰到驗證碼
- 驗收失敗，而且修了兩輪還是過不了
- 現況跟交接單對不上（別台機器推了東西、規格被改了）
- 區塊沒寫清楚、而猜錯會改變**做出什麼**（只影響怎麼做就自己決定，回報時寫假設）
- `blocks.md` 全部打勾——這時寫一次總回報結束，不要自己切新一批

沒碰到這些就不寫「要繼續嗎」、不停在一句話回報。

## 相關

- `grilling` —— 切塊之前先把需求問成規格
- `handoff` —— 收一塊時寫交接單、`handoff-open` 自己 /clear 換手；這個 skill 靠它接到下一塊
- `hooks/README.md` 的「前文回收」—— `session-journal` / `context-tier`（何時該收）
- `project-map.json` 的 `routes` —— 那是「這種事怎麼做」的操作手冊，
  跟 `blocks.md`（「剩下的工作分成哪幾塊」）是兩件事，不要混用同一個檔
