# 工具畫面的設計方向

這裡講的是**每天要用的工具畫面**（後台、儀表板、記帳、清單），不是行銷頁。
行銷頁的規矩（大標、主視覺、動畫）放到工具畫面上幾乎全錯。

數字與規則改寫自 taste-skill 的 `app-screens.md`（23 個真實產品畫面的量測）與
Anthropic 的 `frontend-design`；繁中的字級、行高、字型是這邊另外定的。

## 一、先定 token 再寫

**共用的規格已經寫好了**：`~/.claude/skills/newproj/templates/tokens.css`（變數）＋
`app.css`（骨架：版面、面板、數字列、按鈕、表單、表格、徽章、各種狀態）。
新專案 `scaffold.sh` 會自動複製進 `frontend/src/`；舊專案改造時整份複製過去，再把舊變數對應上。
示範頁 `newproj/templates/demo.html` 每一種元件與狀態各有一個，改樣板就打開它看。

規則：

1. **元件裡不寫色碼、字級、間距、圓角的數字**，一律引用變數。要新的值，先加到 tokens 再用。
2. **專案的長相只改主色**：`--accent`、壓在它上面的字色 `--accent-ink`、指到時的 `--accent-hover`（主色 88%＋`--surface` 12% 算好的固定色），亮暗各一個值、三個一起換。
   `--accent` 也是連結與焦點框的顏色，在 `--surface` 上要過 4.5:1（淺黃綠這種亮色不行）。其餘留著，所有專案才是同一套骨架。
3. **不寫 `style={{…}}`、不寫 inline style。** 動態的值（例如進度條寬度）才例外，而且只傳那一個值。
4. 動手寫之前先寫下四行計畫：主色（為什麼是這個顏色）、這個畫面要回答的一個問題、
   版面（一句話＋ASCII 草圖）、哪一個元素是這個產品才有的。
   **再回頭看：這份計畫拿去配任何一個類似的專案都成立的話，那就是套版，改掉。**

主色怎麼挑：從產品的世界裡拿（菜園拿葉綠、借貸拿銀行的深藍、小說拿紙墨），不要拿「看起來很科技」的顏色。
**不要紫色／藍紫、不要奶油底配陶土色、不要黑底配螢光綠**——那是現在 AI 生成畫面的三種招牌色。

## 二、字

- **一種無襯線字**（tokens 的 `--font`：系統字 → 蘋方 → 思源黑體 → 微軟正黑）。不用 Inter、Roboto、Geist（被用爛，design-scan 會抓）。
  等寬字只給 ID、程式碼。
- **字級六級**：12 標籤／15 內文／17 面板標題／20 區塊標題／24 頁面標題／30 答案數字。一個畫面用 4–9 種。
  工具畫面的標題**不超過 32px**、數字**不超過 40px**——超過就變成行銷頁。
- **繁中內文行高 1.7**（比英文鬆），標題與數字 1.35，表格 1.5。
- 字重最多三種；700 一個畫面只做一件事。字距不要動（大字可以 -0.02em）。

## 三、數字

- **表格裡、KPI 裡、會跳動的數字一律等寬數字**（`tabular-nums`，tokens 對 `table` 與 `.num` 已經開了），**靠右對齊**（`td.num`）。
- **同一種量固定小數位**：錢 0 或 2 位（看幣別）、百分比 1 位、次數 0 位。千分位一律加。變化量一律帶正負號。
- **單位是後面一個較小的灰字**（「128.4 公斤」的「公斤」），不跟數字一樣大。
- **缺值是灰色短橫線「—」，真的零照常印「0」。** 兩個意思不同，不准混。
- **顏色講好壞，不是講漲跌**：延遲、錯誤率、成本、損耗是降了才好。往壞的方向用 `--negative`、往好的用 `--positive` 或灰。**零變化是灰的。**
  **例外：記帳類（錢進錢出）可以用顏色分金流方向**——借／支出 `--negative`、還／收入 `--positive`、利息 `--warning`，
  只上在有金額的格子，缺值的「—」照舊灰（2026-10-23 使用者看過 loan-ledger 後裁示）。
  前一期是 0 的時候寫「+4（新）」，不要寫「+100%」。
- 每一個相對數字講清楚跟誰比（「比上週」「近 30 天」）。
- 同一個數字出現兩次要一致；總數從列加回去要對得上。

## 四、KPI（摘要數字）

- **不是一個數字一張卡**：一個容器用細線分格（`.kpis`／`.kpi`），標籤在上、數字在下。
- 一列 1–6 個，常見 3–4。數字 24px、標籤 12px 灰色。
- **這個畫面要回答的那一個數字最大**（`.value.lead`，30px），其他的都比它小一截；整個畫面沒有比它更大的數字。
- **不要**：圖示放在彩色圓圈裡、每個 KPI 底下一條迷你走勢線、每一格都有綠色「+12.5%」膠囊。
- 同一個數字不要在數字列和下面的面板各出現一次。

## 五、表單

- **標籤在欄位上面**（`.field > label`），不用 placeholder 代替標籤、不用浮動標籤。
- 同一個情境只有一種控制項高度（表單 36px、工具列 30px、手機 44px，tokens 都有）。
- 錯誤寫在欄位底下，講怎麼改（「重量不能是負的」），不是「格式錯誤」。欄位加 `aria-invalid="true"`。
- **停用的按鈕要讀得到字，旁邊講為什麼不能按**（`.hint`）。不要用 30% 透明度讓它看不見。
- 按鈕上的字講按下去會發生什麼：「儲存」「刪除這筆」，不是「送出」「確定」。同一個動作從頭到尾同一個名字。

## 六、畫面狀態（每一種都要做，而且要真的逼出來看過）

| 狀態 | 做法（`app.css` 的 class） |
|---|---|
| **空** | 保留框與標題，一句話＋下一步，橫跨整個區塊（`.empty`）。不放插圖、不放「No data」 |
| **載入** | 最終版面先畫好，數值換成同大小的灰條（`.skeleton`），不閃、資料到了版面不跳。已經有資料時重新整理，舊值留著 |
| **錯誤** | 出在哪一塊就顯示在哪一塊（`.error-inline`），一句話講什麼壞了、上次成功是什麼時候，加「重試」。**不要整頁橫幅，不要把後端回的整頁 HTML 或堆疊印出來** |
| **讀失敗** | 跟「空」是兩件事：讀失敗時不要同時顯示「還沒有資料」 |
| **資料是快照** | 一行安靜的提示（`.notice`），講它不會更新 |
| **用量／上限** | 一條照真實比例的條，兩端都標（「12.7k／20.0k」）|

**紅色是訊號不是質感**：一個物件最多一個紅色記號，放在真正逾期或失敗的那一件事上。

## 七、手機版（390px 每一輪都要看）

- 側欄收起來：變成 48px 的頂列＋選單按鈕，或底部 4–5 個分頁。手機上側欄佔超過 30% 寬就是錯。
- 左右邊距 16px、點擊目標至少 44px、字不小於 12px。標題留著（20px）。
- 數字列變兩欄（單數個時最後一格佔滿，`app.css` 已經做了），不要擠成四欄。
- **表格在 640px 以下變成兩行的清單**：第一行名稱＋關鍵數字，第二行其他欄位（13px 灰字）。欄位搬到第二行，不准丟掉。
  非得維持表格時只在自己的框裡橫向捲動（`.table-wrap`），**整頁永遠不准橫向捲動**。
- 帶動作的區塊（庫存不足＋補貨）往上搬成一行摘要，不要掉到二十筆訂單下面。

## 八、AI 套版的特徵（看到就換掉）

| 套版 | 換成 |
|---|---|
| 深藍或彩色側欄、選中項有彩色膠囊加左側粗線 | 側欄跟頁面同底色；選中只用淡灰底 |
| 「歡迎回來，小明 👋」加副標 | 一個名詞當標題，24px |
| 四張 KPI 卡、每張一個彩色圓圈圖示 | 一個細線分格的容器，標籤＋數字 |
| KPI 數字 36–48px、粗體、主色 | 24–30px、一般字重、墨色 |
| 漸層面積圖、平滑曲線、每個點一顆圓 | 2px 直線、不填色、不加點 |
| 彩虹配色、一根柱子一個顏色 | 一張圖一個色相，其他用中性灰；整個畫面最多四個色相 |
| 圓角 16–24px＋邊框＋大片柔和陰影 | 邊框或陰影二選一；圓角只有三種（`--radius-*`）|
| 斑馬紋表格＋大寫加寬表頭＋每列都有勾選框、頭像、狀態、選單 | 列線與對齊；12px 灰色表頭；需要的地方才放一個動作 |
| 飽和色的狀態徽章配白字 | 淡底深字、同一個色相（`.pill`）|
| 每顆按鈕都是主色 | 只有主要按鈕（`.btn.primary`，一個畫面一顆）用主色，其餘按鈕是白底細框 |
| 匯出、分享、日期選擇器擠在標題旁 | 只放真的有的動作；放一個「資料更新於」時間 |
| 假人名假公司（王小明、Acme）、整數的漂亮總數 | 產品自己的資料、真實大小的小數字、總數從列加出來 |
| 五列的清單底下放分頁 | 只顯示前幾列＋「看全部」＋總數 |
| 深底配霓虹、發光邊框、毛玻璃 | 真中性的深色、亮度分層、顏色只在資料上 |
| 每一節標題上方一行小號大寫眉標；「A · B · C」中點串接；按鈕字後面加「→」 | 刪掉 |

把套版全拿掉、什麼都沒放回去，得到的是一個整齊的範本。**填滿空間的應該是產品本身**：
它自己的資料、這個畫面要回答的問題由最大的那一塊回答、加總對得上的格線。

## 九、介面文案

- 從使用者的角度命名：「通知設定」，不是「webhook config」。
- 主動語態；按鈕講會發生什麼；同一個動作同一個名字（按「發布」，提示說「已發布」）。
- 錯誤不道歉、不含糊：講壞了什麼、怎麼辦。空畫面是邀請下一步，不是表達情緒。
- 一律繁體字；介面上的英文只留專有名詞。

## 十、驗收

寫完照 `inspect-ui` skill 跑（渲染出來、逼出每一種狀態、掃寬度），再用眼睛回答這七題
（`~/.claude/agents/ui-verifier.md` 的目視題是同一份）：

1. 這個畫面要回答的問題，是不是由最大的那個東西回答、而且第一眼就讀到？
2. 每一塊是不是對齊畫面的邊？有沒有一側空一條、卡片短一截、孤兒格、被拉高留一片空白的卡片？
3. 顏色是不是只在資料、狀態、唯一的主要動作上？
4. 數字加得起來嗎、一位一位對齊嗎？出現兩次的數字一致嗎？相對數字講了跟誰比嗎？
5. 零看起來像零、缺值看起來像「—」嗎？計數徽章是不是只放在真的要處理的佇列上？
6. 圖例的色塊跟它解釋的記號一致嗎？有沒有標籤撞到線或撞到別的標籤？
7. 手機上導覽收起來了嗎？每一塊還回答得了自己的問題嗎？

**修最嚴重的三個，再看一次，最多三輪。** 截圖上看得到的問題就是真的問題，不管程式碼怎麼說。

亮暗兩色都要看：網址或 `<html data-theme="dark">` 切換。

## 十一、把樣板接進舊專案（U5〜U12 踩過的）

- **`tokens.css` 與 `app.css` 一起換**：`app.css` 會用到新加的變數（例如 `--primary-hover`），只換一份會有樣式解不出來。
  專案自己的按鈕變體（`.btn.xxx { background: … }`）要自己寫 `:hover:not(:disabled)`，不然會被 `.btn:hover` 蓋成淺灰底。
- **撞名**：樣板的通用 class（`.grid`、`.panel`、`.field`、`.empty`、`.error`、`.hint`）很可能專案自己也有。
  複製前 `grep` 一次撞到的，改專案那邊的名字（例如 `.bar.empty` → `.bar.nodata`），不要讓兩套樣式疊在同一個元素上。
- **Tailwind 專案**：不要整份 import `app.css`——`.grid` 會蓋到 Tailwind 的 `grid` 工具類、`.panel` 多出 grid 與內距。
  只放 `tokens.css` 進 `@layer`，`app.css` 拿掉撞名的 class 再用；不分層的 Tailwind 工具類永遠贏。
- **包第三方元件（畫布、編輯器、地圖）**：用 `@import … layer(template)` 讓元件自己的樣式贏，
  但元件沒寫的屬性照樣吃樣板（`body` 的字級行高、`p`／`h*` 的 margin、表單元素的字），
  要再一層 `canvas-reset` 對元件根節點底下 `revert` 回瀏覽器預設；同名的 `.empty`／`.error` 用 `all: revert`。
  驗法：元件自己的對話框改造前後逐像素比（scaledraw 的做法）。
- **要支援舊 iOS 的（Capacitor app 看 `IPHONEOS_DEPLOYMENT_TARGET`）**：`light-dark()` 要 iOS 17.5、`color-mix()` 要 16.2、
  `@layer` 要 15.4、`:has()`／`100dvh` 要 15.4。低於這些的，顏色每個主題各寫一組固定值（從 tokens.css 抄、檔頭註明要一起改），
  非顏色的 token 也抄一份到不分層的 `:root`（不然 `@layer` 被丟掉時內距全變 0）。
- **`p { margin: 0 }`**：樣板的間距全靠容器的 `gap`（`.panel`、`.app` 都是 grid）。舊畫面把錯誤、空狀態、說明一串 `<p>` 放在
  不是 grid／flex 的容器裡時會全部貼在一起——給那個容器 `display: grid; gap: …`，不要改回 `p { margin }`（在 grid 裡會跟 gap 疊加）。
- **圖表庫讀不到 CSS 變數**（ECharts 這類 canvas 畫的）：`getComputedStyle` 讀自訂屬性拿到的是 `light-dark(...)` 原字串，
  要套到一個元素的 `color` 再讀回算好的 rgb；亮暗切換時重畫。
