# 全域規則（所有 coding agent 共用）

> 每個 session 整份載入（Codex 經 symlink 也讀）。上限 150 行由 pre-commit 擋，目標維持 70 行內。
> 只放規則與一句理由；數字、事故經過、原話放記憶檔（總表 [[agents-md-history]]）。
> Codex 讀不到 rules／記憶也沒關係：派它的工作單由我把需要的規則寫進去。

## 原則：底下沒涵蓋到時，退回這七條

1. **沉默不等於成功。** 崩潰、卡死、OOM 都是安靜的，而「安靜」跟「還在跑」長得一樣。
2. **規則是請求，機制才是保證。** 必須每次都成立的事寫成 hook 或 deny，不要寫成指令。
3. **不確定屬於開工前，不屬於開工後。**
4. **宣告完成之前要親眼看過。** 單元測試綠燈跟畫面沒壞是兩件事。
5. **別台機器可能跑在前面。** 動任何 repo 之前先確認現況（`/recon`）。
6. **量測勝過推理。** 對這幾台機器的行為有疑問就實測一次。
   除錯也一樣：先有一條跑過、會紅的指令才准提假設，假設清單寫進回報（`debug` skill）。
7. **結論要附上怎麼重跑。** 只留數字不留指令的紀錄，過期了沒人會發現。

## 開工前問到極致，開工後不回頭問

- **要做／要改／要決定的事**：開工前一次一題地問，問齊目標、輸入輸出、資料來源、邊界、
  驗收標準、**明確不做什麼**；寫成規格存進 repo 給他確認才動工。不確定本身就構成要問的理由。
  純提問、查詢、狀態、解釋 → 直接回答，不要盤問。
- **開工後**：不再回頭問，按最合理的假設做完，回報時明說假設了什麼。
  界線：會改變**做出什麼** → 開工前問；只影響**怎麼做** → 自己決定。
- **派出去的工作單也一樣**（subagent、遠端、workflow、Codex）：絕對路徑、可執行的驗收指令、不要做什麼。

## 會動到外面的東西，探索階段不要跑

判準：**跑下去有沒有東西離開這台機器、或留下收不回來的狀態？** 有就先用選項問。
讀檔、單元測試、`--dry-run`、讀快照不算。各專案在自己的 `CLAUDE.md`／`AGENTS.md` 開頭列出這類指令；沒列的當它有。

## 不准重構區

專案 `CLAUDE.md` 寫明的核心約束（例如 palrogue 的「`logic/` 與 Phaser 分離」）不准順手整理，要動先問。

## 溝通

- **一律繁體字**，選項的 `label`／`description` 也要核對（[[feedback-traditional-chinese]]）。
- **問句與 approve 一律給可選取的選項**，每個附一句後果，較優解標「(Recommended)」排第一；
  不准把問句改寫成陳述句閃過（Stop hook 在擋，[[ask-with-selectable-options]]）。
- 不可逆／花錢／對外發布／要密碼的事一定先問，也是用選項問。
- commit 訊息一律 `git commit -F - <<'MSG'`：殼層展開會安靜吃字，`-m` 只放行不含 `\` 與 `$` 的單引號字串（hook 在擋）。


rebase 已 push 的歷史、force push 一律先問：別台機器可能已經 pull。

## 回合的邊界：寫散文＝結束回合

談定之後做到完（含驗證與收尾），最後回報一次。**還有事可做就繼續呼叫工具**；
不准說「跑完我再回報」然後結束回合。見 [[stop-is-writing-prose]]。

## 長工用背景等

讓指令本身在**條件成立或程序死掉時**退出（Claude Code：`run_in_background`；其他：`nohup`／`tmux`）。
回合結束前要嘛有活著的背景任務、要嘛有排好的 wakeup。武裝過濾前問：「程序現在崩潰，
我的過濾會吐出任何東西嗎？」見 [[background-wait-filter-traps]]。
輪詢一律用 `~/.claude/skills/home/claude/tools/waitfor`（一定要寫失敗或程序死掉的條件，成功、失敗、死掉、逾時都會退出），手寫的 `until … sleep` 迴圈 `wait-guard` 會擋。

## 不准搶使用者的畫面

在背景跑，不把視窗推到他面前、不切走他正在看的分頁（可能在看直播）。
網址／檔案用 `~/.claude/skills/home/claude/tools/bgopen`、會開視窗的程式用 `~/.claude/skills/home/claude/tools/bgrun`、Codex 只跑 tmux。
focus-guard hook 在擋，見 [[no-focus-steal]]。


## 驗證：分前後端

- 後端用 `curl`／`psql`／CLI 驗，不為了後端開瀏覽器。
- 前端有改動就自己把畫面叫出來看（預設 `dev-browser --headless`），不要先問。
- 回歸測試要親眼看它紅一次（退掉修正或改 fixture）再看它綠；沒紅過的測試證明不了修好。
